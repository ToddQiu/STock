# STock 阿里云上线操作手册

更新：2026-10-26。本包尚未部署到公网；不购买服务器、不付费、不申请付费 API。目标是获得可私下分享的 HTTPS 网址，不是 GitHub Pages 静态研究页。网页部署与微信小程序审核互相独立。

## 上线范围

| 内容 | 云端状态 |
| --- | --- |
| 总览、持仓组合、市场、事件、指数、股票池、研究、ETF、财报、回测、估值、设置 | 沿用当前网页与 Python 后台 |
| 组合与研究数据 | 新建独立 SQLite 工作区，初始空持仓、零本金；不上传本机私人数据库、配置、笔记或密钥，不自动与桌面同步 |
| 使用者 | 同一密码可看、修改、导出同一份数据；没有独立账号、只读访客或逐人授权 |
| 公开行情与新闻 | 不采购 API；可用性、延迟和使用授权取决于来源，接口成功不等于实时数据有效 |
| 新闻翻译 | 服务器构建时下载并核验翻译模型，翻译质量仍需复核 |
| STock Ai 问答 | 当前仅桌面本机启用，云端接口明确拒绝；本包不含本机问答模型，不解除该限制 |
| Windows 弹窗与窗口按钮 | 桌面能力；云端用站内事件中心，不提供手机后台推送 |

**先用于受邀团队共享，不作为陌生人可注册的商业 SaaS。** 独立账号、只读权限、云端 AI 尚需开发。公开收费前还应修复已知的新闻归属、机器翻译和估值输入边界问题，并核对财经内容与数据再分发权限；部署成功不证明分析结论可靠。

## 1. 购买专用服务器

1. 登录阿里云并完成所需实名认证，打开“轻量应用服务器 → 创建服务器”。
2. 地域“中国香港”；“系统镜像 → Ubuntu → 24.04”；架构 x86-64 / amd64。不要选 Windows、ARM 或预装宝塔、WordPress 的镜像。
3. 初始建议：4 vCPU、8GB 内存、70GB 或更大系统盘、1 个公网 IPv4，数量 1，先 1 个月。这是小范围试用起点，不是并发量承诺。轻量套餐不合适再选同配置 ECS。
4. 核对首期实付、续费、流量配额和超额费用，取消自动续费。不加购 GPU、RDS、负载均衡、付费证书和模型套餐；订单与条款由你确认后付款。
5. 等实例“运行中”，记录公网 IP、地域、系统、到期日。不要在已有其他业务的服务器上运行本包。

此前 224 元是 2026-10-16 历史报价，不是当前售价。官方说明创建页默认开启自动续费；“无固定流量”套餐不收超额流量费，有配额套餐可能收取，最终以购买页为准。[创建服务器](https://help.aliyun.com/zh/simple-application-server/user-guide/create-a-server)、[计费项](https://help.aliyun.com/zh/simple-application-server/product-overview/billable-items)。

香港节点不适用中国内地服务器的 ICP 备案流程，但可能增加内地访问延迟，也不能保证海外数据源可用；不代表免除其他合规义务。选择中国内地节点时需先完成适用的 ICP 备案，不能部署完就直接分享。[阿里云备案说明](https://help.aliyun.com/zh/simple-application-server/user-guide/apply-for-an-icp-filing-for-a-domain-name)。

## 2. 域名与防火墙

1. 准备你有 DNS 管理权的域名。已有域名可增加子域名，无需重复购买。本方案需要域名来签发和校验 HTTPS，不用裸 IP 分享。
2. 在 DNS 服务商增加 A 记录：主机记录 `stock`，值为服务器公网 IPv4，TTL 用默认值。最终类似 `stock.example.com`，必须换成真实域名。
3. 只清理该子域名冲突的旧 A、AAAA 或 CNAME，不动其他业务记录。先关闭这个子域名的 CDN 代理。运行 `Resolve-DnsName stock.example.com`，确认只指向目标 IP。
4. 轻量实例进入“防火墙”；ECS 进入“安全组 → 入方向”。TCP 80/443 允许 `0.0.0.0/0`；TCP 22 限为你的管理网络公网 IP `/32`。先验证 SSH，再收紧旧规则，保留控制台恢复入口。
5. 系统内部若启用了 UFW 等防火墙，也需放行必要端口。不要开放 8080、8765、数据库、Docker 管理端口或“全部 TCP”。

Caddy 自动申请和续期证书，不需购买付费证书；域名解析和 80/443 必须正常。[防火墙操作](https://help.aliyun.com/zh/simple-application-server/user-guide/manage-the-firewall-of-a-server)。

## 3. SSH 密钥登录

1. 在实例密钥管理中创建并绑定密钥，或导入已有公钥。私钥只存在本机安全位置，不发聊天、不上传仓库。若提示重启，只操作这台新建实例。
2. 用户名以控制台为准，以下以 root 为例。非 root 用户还需能执行 `sudo -n python3 --version`。
3. 通过阿里云控制台远程连接，运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，获取主机公钥指纹。本机首次 SSH 连接只接受相符指纹；若提示其他类型，要核对相应公钥文件，不关闭校验。

```powershell
ssh -i "$HOME\.ssh\stock_aliyun" root@你的公网IP
```

密钥路径替换成实际文件。登录后检查 `uname -m` 为 `x86_64`，`cat /etc/os-release` 为 Ubuntu 24.04，`python3 --version` 可用，再 `exit` 返回 Windows。密钥有口令时先在受信任的本机 SSH agent 中解锁；自动化使用 BatchMode，不支持逐次输入登录密码。

```powershell
ssh -i "$HOME\.ssh\stock_aliyun" -o StrictHostKeyChecking=yes -o BatchMode=yes root@你的公网IP "python3 --version"
```

上述非交互登录成功后再部署。脚本不会自动信任陌生主机，也不收集阿里云 AccessKey。

## 4. 一次运行上线包

解压整个包，在该目录打开 PowerShell。先离线检查，不连接服务器、不收费：

```powershell
.\Launch-STock.ps1 -CheckOnly
```

再运行下列命令，域名不带 `https://` 或末尾斜杠。已有默认 SSH 密钥时也可双击 `Launch-STock.cmd`，填写服务器与域名。

```powershell
.\Launch-STock.ps1 -Server root@你的公网IP -Domain 你的域名 -Port 22 -IdentityFile "$HOME\.ssh\stock_aliyun"
```

入口会校验包、SSH、DNS，安装官方 Docker，下载并构建后台和翻译模型，创建持久卷与随机密码，启动 HTTPS，检查 26 个前端资源和 19 个 API（含回测、估值、多组合）。至少需 12GiB 可用磁盘；首次构建可能十几分钟以上，视网络和机器而定。这不是免联网的 Docker 镜像包。

执行策略禁止脚本时，先查看脚本并按本机组织策略处理；本包不会关闭执行策略。首次失败用同一包、同一域名重试，不随便换包覆盖 pending 状态。

## 5. 验收后分享

1. 自动脚本显示成功网址后，用浏览器打开 HTTPS 地址，不能有证书警告。
2. 用户名 `stock`。通过已验证 SSH，在服务器私下运行 `cat /opt/stock/access-key.txt` 读取密码，非 root 用户需 sudo。不要把输出贴到聊天、公开日志或截图。
3. 另开隐私窗口，不输入密码应被拒绝。不能关闭认证，也不能把密码放进网址。
4. 打开各业务页，检查图表、公司名跳转、对话框和保存按钮。新建“上线验收”组合，测试持仓、本金、基准货币、警戒线、切换和删除，不把测试数据当真实交易。
5. 回测先跑教学案例，再跑真实日线并保存；估值用完整输入计算、保存、重开。缺数据应显示缺失，不能当成零。
6. 等首轮采集完成，核查报价时间、新闻原文、ETF 持仓日期、财报日期与翻译。区分限流、休市和缓存，不能只看接口 200。
7. 重启应用确认组合和研究仍在；用手机移动网络、朋友的外部网络复测。云端与桌面不会自动合并数据。
8. 验收通过后，网址与密码分开私发给受邀者，并说明“共享工作区，修改对所有人可见”。只放同意共享的数据，多人修改同一记录前协调。

真实 HTTPS、外网、手机、数据源连通和研究质量未验收前，不能称为完整上线成功。需要独立账号、只读权限或云端问答，应先补能力再扩大范围。

## 6. 备份、升级与回退

在上线包目录执行，可追加首次使用的 `-IdentityFile` 和 `-Port`：

```powershell
.\Launch-STock.ps1 -Server root@你的公网IP -Action status
.\Launch-STock.ps1 -Server root@你的公网IP -Action verify
.\Launch-STock.ps1 -Server root@你的公网IP -Action backup
.\Launch-STock.ps1 -Server root@你的公网IP -Action rollback
```

- 升级用经过测试的新包再次 install。先构建，再短暂停服务制作一致性备份；失败尝试回退。不承诺零停机。
- 回退用升级前备份恢复到新卷，保留失败版本卷；升级后的修改不在旧备份中，回退前先备份最新数据。首次部署没有旧版本可回退。
- 备份在 `/opt/stock/backups`，同机备份不等于异地备份。首次验收后、重要修改前及定期人工备份，再通过已验证 SSH/SCP 保存备份、校验文件、current.json、previous.json（存在时）、密码及对应版本包到安全位置。非 root 用户请管理员协助，不放宽目录权限来迁就下载。
- 服务器丢失须用对应版本和备份重建，证书可重新签发。独立新机灾难恢复仍须演练，不等于已验证的升级回退。
- 不执行 `docker compose down -v`，不删 workspace 卷。脚本不删历史备份或镜像，定期检查磁盘；空间不足会停止部署。
- 服务器和域名分别续费。自动续费保持关闭，到期前手动决定是否续费。

## 7. 常见失败处理

| 现象 | 检查 |
| --- | --- |
| 校验失败 | 重新取得完整可信的包，不绕过校验 |
| SSH preflight failed | 用户名、密钥、指纹、SSH agent、22 端口来源 IP、非交互 sudo |
| DNS 不匹配 | 该子域名 A/AAAA/CNAME、代理及生效情况 |
| Docker / 模型下载失败 | 出站网络、磁盘和完整报错；不关闭 TLS 校验、不换不明镜像源 |
| HTTPS health check failed | 域名及 80/443；服务器运行 `docker ps`，再用 `docker logs --tail 100 容器名` 看 app / https 日志 |
| 页面正常但没行情 | 软件数据状态、来源时间、交易时段和限流；不把旧值伪装实时 |
| 手机反复登录 | 完整 HTTPS 地址、用户名、密码；先用系统浏览器独立打开 |
| STock Ai 不可用 | 当前云端未启用，不能靠开放端口解决 |

处理后再 verify。不要转发含密码、私钥或私人持仓的调试日志。
